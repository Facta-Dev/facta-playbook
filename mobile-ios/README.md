# `<app>` — native iOS skeleton

A native iOS template: Swift 6 with strict concurrency, SwiftUI, iOS 18, an
XcodeGen `project.yml` that generates the project file, **one SwiftPM package
per architectural layer**, typed routes, a unidirectional-data-flow `notes`
slice, and an explicitly wired composition root. Every `<app>`, `<APP>` and
`<scope>` token is a **literal placeholder** — the module and bundle names are
invalid until you rename, so the template root does not build. See
[How to apply](#how-to-apply).

Status: **ready** — the portable gates pass everywhere; the native gates
(`swift test`, `xcodegen generate`, `xcodebuild`) are pending a macOS/CI run
and print a visible `SKIP` elsewhere.

## Layout

```
<app>/
├── Apps/<APP>/Sources/        # the app target: @main, AppEnvironment, Router, RootView
├── Packages/
│   ├── Core/
│   │   ├── Kernel/            # pure Swift: Outcome, AppError, NoteID
│   │   └── UICore/            # UiStatus, the closed status set
│   └── Feature/Notes/         # the example slice — replace with your domain
│       ├── Contracts/         #   pure Swift: NotesRoute, typed routes
│       ├── Domain/            #   entity, port, use case
│       ├── Data/              #   the in-memory adapter
│       └── UI/                #   SwiftUI screens + @Observable model
├── evals/                     # the .claude contract tests (node --test) + live tier
├── scripts/                   # rename · verify-template · check-architecture · native-gates · linters
├── .claude/                   # 11 agents · 9 skills/commands · schemas · hooks
├── docs/                      # 00–14 · adr/ · admin-guide · data-flows · dependency-register
├── PLAYBOOK_*.md              # seven local contracts — read on demand
├── project.yml                # XcodeGen: one app target, six local packages
├── AGENTS.md                  # agent instructions; CLAUDE.md is a symlink to it
├── MEMORY.md                  # durable premise: packages, routes, UDF, stack
└── Makefile                   # ci · test · build · evals · lint · generate · verify
```

## The package model

The dependency edge is declared in each `Package.swift`, which makes the
architecture a build fact. `NotesUI` never depends on `NotesData`; the app
target chooses the adapter. `Kernel`, `UICore`, `NotesContracts` and
`NotesDomain` are pure Swift packages — a SwiftUI or UIKit import there does
not compile. `scripts/check-architecture.sh` gates the edges the compiler
cannot catch.

`NotesRoute` is a `Hashable` enum; `RootView` maps every case through
`navigationDestination` inside a typed `NavigationStack(path:)`.
`NotesViewState` flows down, `NotesEvent` flows up, and `NotesEffect` leaves
once through an `AsyncStream`.

The project file is generated by XcodeGen from `project.yml` and is
git-ignored — a build setting is changed in `project.yml`, never in Xcode.

## The gate

```sh
make ci                          # lint + contract evals + native gates
make lint                        # check-architecture; after rename, also the .claude linters + budget
make evals                       # node --test evals/contracts.test.mjs
bash scripts/check-architecture.sh
bash scripts/native-gates.sh     # swift test per package + xcodegen + xcodebuild (macOS)
```

Requirements: Node 24 for the contract evals; macOS with Xcode 16+ and
XcodeGen for the native tier. Off macOS the native tier reports `SKIP` and
exits 0, so `make ci` stays green on Linux CI.

## Working with agents

`AGENTS.md` (symlinked as `CLAUDE.md`) is the operating instruction file:
hard rules, the never-list, the package table, the gates, the spec → test →
code workflow and the playbook index. `MEMORY.md` holds the premise — the
package graph, the routes, the UDF contract, the status set, the stack.

Seven local contracts ship next to this file and load **on demand** through
path-scoped rules, never as `@`-imports:
`PLAYBOOK_MOBILE_IOS_SWIFT.md` (architecture, SwiftPM, UDF, navigation,
platform features), `PLAYBOOK_TESTS.md` (tiers, fixtures, gates, audit
evidence), `PLAYBOOK_SECURITY.md` (threat model, Keychain, ATS, secrets),
`PLAYBOOK_FRONTEND.md` (the cross-client UI contract), `PLAYBOOK_URLS.md`
(route and API naming, the error envelope), `PLAYBOOK_AUDIT.md` (SOC 2 /
ISO 27001 / ISO 9001 programs) and `PLAYBOOK_CLAUDE_CODE.md` (the kit,
SDD + TDD loop, governance).

The `.claude/` layer ships 11 agents across four divisions (`core`, `client`,
`security`, `testing`), 9 skills with 1:1 slash commands (`/add-slice`,
`/add-package`, `/add-route`, `/add-port`, `/review`, `/spec`, `/plan`,
`/learn`, `/ship`), schema-driven linters in `scripts/`, a `PreToolUse` Bash
guard, and a `manifest.json` target matrix for installing the kit into other
agent runtimes.

## How to apply

1. Copy this directory to your repo root.
2. `bash scripts/rename.sh <app> <scope>` — substitutes `<scope> → <APP> →
   <app>` in text files and renames the `Apps/<APP>` directory. Both arguments
   must match `^[a-z][a-z0-9]*$` (they become a module name and a bundle-id
   segment).
3. `xcodegen generate` (or `make generate`) — the project file appears; it is
   git-ignored.
4. `make ci` — green; the native tier needs macOS + Xcode.
5. Replace the `notes` example slice with your domain.

### Installing the `.claude` runtime

The kit installs the same agents, skills and commands into other agent
runtimes (Cursor, Codex, Gemini, Zed, …) from the target matrix in
`.claude/manifest.json`:

```sh
bash scripts/install-claude-runtime.sh                        # claude + claude-project
bash scripts/install-claude-runtime.sh --targets=cursor,codex # opt-in runtimes
```

It is idempotent and never clobbers a file you already own — a pre-existing
destination is skipped with a warning, and every operation is recorded in
`.claude/install-state.json`. `bash scripts/verify-template.sh` stages a
throwaway copy under `/tmp`, renames it and runs every gate on the copy.

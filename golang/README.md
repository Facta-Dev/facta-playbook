# `<app>` — Go backend skeleton

A hexagonal, vertically-sliced Go 1.27 backend template: stdlib `net/http`
ServeMux, pgx/v5, sqlc, goose, godog acceptance tests, golangci-lint v2 with
depguard slice-isolation. Every `<app>`, `<APP>` and `<scope>` token is a
**literal placeholder** — the module path is invalid until you rename, so the
project cannot build (and `go.sum` is intentionally not committed). See
[How to apply](#how-to-apply).

## Prerequisites

- Go **1.27** (`go version`). Raise the floor by updating `go.mod`'s `go`
  directive and the CI matrix together.
- Postgres 17 for the integration suite — provided automatically by
  testcontainers (`-tags=integration`); a plain `docker` install is the only
  requirement. `docker compose up -d` manages a local dev Postgres.
- `sqlc` and `goose` run through `go tool` (module tool deps) — no global
  installs needed; `golangci-lint` v2 is installed separately (a binary, not
  a `go tool` module dep).
- godog runs as a normal `go test` dependency — no binary install.

## The gate

```sh
make ci                  # gofmt check + go vet + golangci-lint + gen-check + go test
make test-int            # -tags=integration: testcontainers Postgres (adapters + migrations)
make accept              # godog over the fake-wired mux (no DB, fast)
```

CI (`.github/workflows/ci.yml`) runs the same three suites. Unit tests are
fake-based and need no database; integration tests tag themselves
`//go:build integration` so the default `go test ./...` skips them.

## Auth ships here

Unlike some siblings in this template batch, this template **does** ship a full
authentication/authorization core — it is not a "wire your own auth" skeleton:

- Signup (idempotent) → email verification codes → login with inactive/blocked/
  unverified gates → JWT access (15m) + rotating opaque refresh (720h) →
  logout/me (read + partial profile update: absent fields are kept, an explicit
  empty string clears a value — presence is expressed by the pointer, never
  NULL) → forgot/validate/reset/change password (codes 30m, rate-limited
  3/5min, reset auto-verifies and revokes sessions).
- Roles `ADMIN ⊃ MODERATOR ⊃ USER ⊃ GUEST` (one definition, `internal/shared/rolex`),
  `authx.RequireAuth` / `authx.RequireRole` middleware, admin surface writing
  audit logs. Admin writes pass the shared `authz` guard: self-or-strictly-
  subordinate — an ADMIN cannot touch another ADMIN, and a stale token role
  never outranks the row's DB role.
- Session management: own list (active by default, `?active_only=false` for
  rotation history), current, revoke-current, revoke-all, admin-side variants
  (`/api/v1/admin/auth-session/...`) and the multi-IP anomalies report.
- Social sign-in: Google One Tap (RS256 ID token verified against Google's
  JWKS) + GitHub auth-code flow — link by provider id, else email, else
  provision an auto-verified user. Disabled by default GitHub; Google needs
  only a client id (both refuse under `<APP>_OFFLINE=true`).
- A worker janitor purges expired sessions and stale verification/reset codes
  every `<APP>_JANITOR_POLL` (default 1h) — run `cmd/worker` alongside the API.
- Email goes through the outbox (`email_jobs`) with a polling worker, retries
  with jittered backoff, and dead-lettering — templates in `en` + `es`.

Replace nothing to keep auth; to re-key any TTL or gate, edit `.env` values
documented in `.env.example`. To drop a surface (e.g. no admin API), remove the
slice's `Register` call from `cmd/api/main.go` — nothing else references it.

## Working with agents

`AGENTS.md` (symlinked as `CLAUDE.md`) is the operating instruction file: hard
rules, layout, commands, the spec → test → code workflow, who edits what, and
the playbook index. `MEMORY.md` holds the premise — actors, slices, owned
tables, invariants — so a fresh session does not have to rediscover it.

Six backend contracts ship next to this file:

| File | Covers |
|---|---|
| `PLAYBOOK_BACKEND.md` | Architecture, slices, dependency rules, persistence, worker, realtime |
| `PLAYBOOK_TESTS.md` | Test pyramid, tags, environments, gates, SOC 2 / ISO 27001 evidence |
| `PLAYBOOK_SECURITY.md` | Threat model, authn/authz, input, secrets, supply chain, incident |
| `PLAYBOOK_URLS.md` | Route naming, namespaces, error envelope, streaming |
| `PLAYBOOK_AUDIT.md` | Running an audit program (SOC 2 / ISO 27001 / ISO 9001) |
| `PLAYBOOK_CLAUDE_CODE.md` | The Claude Code kit, SDD + TDD loop, multi-session governance |

The `.claude/` layer ships 11 agents across four divisions (`core`, `backend`,
`security`, `testing`), 9 skills with 1:1 slash commands (`/add-handler`,
`/add-module`, `/ownership-author`, `/depguard-guard`, `/review`, `/spec`,
`/plan`, `/learn`, `/ship`), schema-driven linters in `scripts/`, a
`PreToolUse` Bash guard, and a `manifest.json` target matrix for installing the
kit into other agent runtimes (`scripts/install-claude-runtime.sh`).

```sh
bash scripts/lint-agents.sh && bash scripts/lint-skills.sh && bash scripts/lint-commands.sh
bash scripts/leak-guard.sh
```

## How to apply

Echo of the template README's six steps:

1. Copy this `skeleton/` to your repo root.
2. `bash scripts/rename.sh <app-slug> <org-scope>` — the script applies the
   `<scope> → <APP> → <app>` substitutions in safe order.
3. `go mod tidy` — creates `go.sum`; the pinned requires in `go.mod` stay valid.
   (The Docker build self-heals a missing go.sum — see the Docker section —
   but keep the committed go.sum for reproducible `-mod=readonly` builds.)
4. Commit `go.mod` + `go.sum`.
5. `make ci` — green.
6. Replace the `widgets` example slice with your domain.

## Docker

After the rename, `docker compose up -d` is the whole dev boot path: the
`migrations` service applies the schema (the API never migrates itself —
replicas would race), then `api` starts on `:8080` and the `worker` janitor
runs alongside. Migrations on the host remain `make migrate-up`; the prod
release step is
`docker compose -f docker-compose.prod.yml --profile tools run --rm migrations`
(the same `/migrate` binary; no third-party migration image).

## Offline guard (INV-T7)

`<APP>_OFFLINE=true` selects the console/noop mailer unconditionally and
disables outbound sockets from the platform adapters: `internal/platform/email`
never reads `<APP>_SMTP_*` (the `Sender` is `Console`, which logs the rendered
email); the API and worker boot with no dial-out, the outbox worker still runs but nothing leaves the process, and the
realtime hub stays in-process (it already is), and the OAuth flows (Google
JWKS fetch, GitHub token/user exchange) refuse with a config-style error at
the request boundary instead of dialing out. The selector is a plain function
`email.SelectSender(cfg, slog.Default())` — no new interface; `cmd/api/main.go` and
`cmd/worker/main.go` are the only call sites. Acceptance tests wire the console
sender explicitly; the guard exists so a fresh `.env` copy with dummy values
plus `OFFLINE=true` boots a fully working stack.

To exercise the SMTP path locally, point `<APP>_SMTP_HOST`/`_PORT` at a local
mailpit-style sink with `<APP>_OFFLINE=false`.

## ponytail notes

Deliberate stubs are marked `// ponytail:` with the ceiling and upgrade path
(e.g. the in-process hub "single-process fan-out; Redis pub/sub adapter when
you need multi-replica"). Migrations deliberately do **not** run at server
startup — apply them with `make migrate` (`go tool goose up`) in your deploy
step.
